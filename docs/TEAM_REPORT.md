# 페어카 팀 공유: Pleos 화면 구성 검증 결과

> 2026-10-29 · Pleos Connect Emulator v2.1.0 + NaviHelper SDK 3.0.5로 직접 확인 · 상세: [PLEOS_FEASIBILITY.md](PLEOS_FEASIBILITY.md)
> **화면 시안 PDF (에뮬레이터 캡처, 분할 화면 포함)**: [PairCar_Split_Screen_Mockup.pdf](PairCar_Split_Screen_Mockup.pdf) · 원본 HTML: [split_mockup.html](split_mockup.html)

## 한 줄 결론

**"내비 위 팝업"은 안 된다. 대신 "Driving view(내비 TBT) + 내비 + 페어카" 분할 화면이 되고, 페어카 앱에서 내비 경로(경유지 포함)를 직접 설정할 수 있다.**

## 1. 현재 구현 가능한 기능 (에뮬레이터에서 직접 확인)

- 페어카 앱이 Pleos 앱 영역에서 실행됨 (홈 · 매칭 · 상세 · 주행 화면, Mock 데이터)
- **내비 연동 (NaviHelper SDK, 별도 신청 불필요)**
  - 버튼 하나로 **픽업 지점 2곳 + 목적지** 경로 설정 → 내비가 3초 뒤 자동 안내 시작
  - POI ID 없이 **좌표만**으로 경로 설정 가능
  - 내비에서 남은 거리/시간을 받아 앱에 ETA 표시 (내비 화면 시각과 일치)
  - 내비 화면 열기, 경로 개요 보기, 경로 취소
- **분할 화면**: window bar를 끌면 [Driving view | 내비 | 페어카] 동시 표시. 페어카는 좁은 창에 맞춰 1단 레이아웃으로 자동 전환
- **주행 규제 대응**: 기어 D가 되면 (CarUxRestrictions) 자동으로 주행 화면만 표시, 탑승 확인 같은 조작은 정차 후로 제한
- 주행 중에도 Driving view(왼쪽 고정 영역)에 **내비 TBT(“80m 좌회전”)** 가 계속 보임

## 2. 안 되거나 공식적으로 확인 안 된 기능

| 기능 | 상태 |
|---|---|
| 내비 위에 페어카 팝업 띄우기 | **불가**. NaviHelper에 오버레이 기능 없음, “다른 앱 위에 표시” 권한 설정 화면 자체가 없음, Driving view는 앱이 가릴 수 없다고 문서에 명시 |
| 알림을 Heads-up(화면 위 배너)으로 띄우기 | 알림 센터에는 들어가지만 **배너는 안 뜸**(시스템 앱만 허용하는 것으로 보임). 공식 문서 없음 |
| 앱이 직접 분할 화면 만들기 | **API 없음**. 사용자가 window bar/3손가락 제스처로만 조작 |
| 경유지 3곳 이상 | 불가 (FIRST/SECOND 2곳). 3명 이상이면 앞 픽업 후 경로 재설정 |
| 픽업 지점 도착/목적지 도착 이벤트 | 코드는 있음. 에뮬레이터는 차 속도만 바뀌고 내비 위치가 안 움직여서 확인 불가 → 실차/Devbox 필요 |
| **페어카 화면 안에 Pleos 내비 지도 넣기** | **불가**. 지도를 넘겨주는 API 없음. Google 지도도 불가(Play 서비스 없음) |
| 페어카 화면 안에 **우리 지도** 그리기 | **가능 (확인)**. MapLibre 지도 SDK로 마커·선·색 모두 커스텀. 단, 내비와 똑같은 경로선은 못 받음 |

## 2-1. 와이어프레임(V-02/V-06/V-07/V-08) 기준 정리

| 와이어프레임 요소 | 가능? | 어떻게 |
|---|---|---|
| V-06 왼쪽 속도 78km/h, "450m 좌회전" | 이미 됨 | Pleos Driving view(시스템). 우리가 만들 필요 없음 |
| "403m 남음", "경유지1 4분", "도착 08:34 · 82.1km" | 가능 | NaviHelper `onWayPointInfo`, `onDestinationInfo` (단위: m, 초) |
| 지도 + 출발/경유/도착 마커, 내 차 위치 | 가능 | 자체 지도 SDK + `getCurrentLocationInfo` |
| 지도 위 파란 경로선 | 조건부 | 별도 길찾기 API 필요, Pleos 내비 경로와 다를 수 있음 |
| 주행 중(V-06) 앱 지도 | 확인 필요 | 지도 허용 예시는 Maps/Navigation 카테고리에만 있음 → Pleos 문의 |

→ **추천**: 정차 화면(V-02, V-07, V-08)은 자체 지도로 와이어프레임대로 구현. 주행 중(V-06)은 지도는 옆의 Pleos 내비에 맡기고, 페어카 화면은 "403m 남음 / 경유지 4분 / 도착 08:34" 같은 큰 숫자 카드 위주로 하되, 지도 표시가 허용되면 간결한 지도(마커+내 위치, 애니메이션 없음)를 추가.

## 2-2. NaviHelper API 점검 (22개 전부 호출해 봄)

- **동작 확인**: 연결, 리스너, 경유지 포함 경로, 경유지 삭제, 경로 취소, 상태/목적지/경유지 조회, **TBT(회전 안내) 조회**, **현재 위치 조회**, 최근 목적지, 즐겨찾기, 충전 사업자, **예상 거리·시간 조회(requestTrip)**, 내비 화면 열기·경로 개요·장소 검색 화면
- **요청은 전달, 결과 콜백 미확인**: 경유지 추가, 경로 옵션 변경, 재탐색
- **에뮬레이터로 확인 불가**: 경유지/목적지 도착 콜백
- 상세 표: [PLEOS_FEASIBILITY.md](PLEOS_FEASIBILITY.md) "NaviHelper API 전수 점검표"

## 3. 직접 테스트한 결과

| 테스트 | 결과 |
|---|---|
| 에뮬레이터 부팅 (Intel 내장 GPU, 공식 사양 미달) | 성공 (약 90초) |
| 빌드 / 단위 테스트 | `assembleDebug` 성공, 단위 테스트 11개 모두 통과 |
| NaviHelper 연결 | 성공 (내비 서비스 3.0.4) |
| 경유지 2개 + 목적지 경로 요청 | 성공, 내비 자동 안내 시작 |
| 내비 화면 열기 / 경로 개요 / 경로 취소 | 성공 |
| 경유지 추가(addWaypoint) | 내비까지 요청은 전달됨, 화면 반영은 미확인 |
| 분할 화면 (내비 + 페어카) | 성공, 주행 중에도 유지 |
| 기어 D → 주행 화면 자동 전환 | 성공 |
| 알림 Heads-up | 배너 안 뜸 |

테스트 중 고친 버그 3개: ① 내비 서비스가 문서와 다른 콜백(`onRouteEnded`)을 보냄 ② 경로 시작 정보가 "첫 경유지까지" 값이라 목적지로 착각 ③ 앱 아이콘으로 다시 열 때 화면이 중복 생성됨(`singleTask` 적용)

## 4. 추천 주행 중 화면 구성

```
┌──────────────┬──────────────────────┬──────────────────────┐
│ Driving view │   Navigation (지도)   │   페어카 (portrait)   │
│ (시스템 고정)  │   경유지 포함 경로     │  다음 픽업 · 김민지     │
│  80m 좌회전   │   안내 중             │  판교역 1번 출구       │
│  (내비 TBT)   │                      │  07:08 도착 · 약 10분  │
│              │                      │  탑승 0/2명           │
│              │                      │  [ 내비 보기 ]         │
└──────────────┴──────────────────────┴──────────────────────┘
```

1. **출발 전 (정차)**: 페어카 앱에서 오늘 카풀 확인 → **[카풀 시작] 한 번** → 페어카 앱이 내비에 픽업 지점(경유지)과 회사(목적지)를 설정
2. **주행 중**: 사용자가 window bar로 [내비 | 페어카] 분할. 페어카는 **다음 픽업 장소, 도착 예정 시각, 탑승 인원** 3가지만 크게 표시
3. **픽업 지점 정차 시**: [탑승 완료] 한 번 → 다음 픽업으로 자동 전환
4. 팝업 대신: 픽업 도착은 페어카 화면 상태 변경 + 알림 센터 알림 (추후 TTS 음성 안내 검토)

### 추천 근거

- **공식 지원 범위 안**: 분할 화면(앱 영역 최대 2개)과 NaviHelper는 문서에 있는 기능이라 심사 리스크가 낮다. 오버레이는 설정 경로조차 없어 시도할 이유가 없다.
- **이미 동작 확인**: 위 구성 전체를 에뮬레이터에서 실제로 띄워 봤다 (스크린샷 `docs/screenshots/07_split_navi_and_app_driving.png`).
- **운전자 주의 분산 최소화**: 주행 중 조작은 "내비 보기" 하나. 텍스트 입력·목록 탐색 없음. 경로는 출발 전에 미리 정해진 프리셋으로 설정.
- **내비를 대체하지 않음**: 길 안내는 Pleos 내비가 하고, 페어카는 "누구를, 어디서, 언제"만 보여준다. 내비 TBT는 Driving view에 항상 남는다.

### 주의할 점

- 페어카가 혼자 크게(landscape) 떠 있는 상태에서 [카풀 시작]/[내비 보기]를 누르면 **내비가 앞으로 나와 페어카를 가린다**. 분할 상태에서는 가리지 않는다. → 첫 실행 시 "내비 옆에 두고 쓰세요" 안내 문구를 검토.
- 분할은 사용자가 직접 해야 한다 (앱이 강제할 수 없음).

## 5. 추후 추가 검증 항목

1. Virtual Console로 실제 주행(ACCEL)을 시뮬레이션해 **경유지 도착 / 목적지 도착 콜백** 확인
2. `addWaypoint` 가 실제 경로에 반영되는지, 경유지 3명 이상일 때 재경로 흐름
3. 서드파티 앱 **Heads-up 알림 허용 여부** Pleos 문의
4. `distractionOptimized` 선언과 앱 카테고리(**Mobility Services** 예상) 심사 기준 사전 문의
5. 폼 팩터 테스트(12.9 / 14.6 / 17인치, Connect-W)로 portrait 레이아웃 확인, 글자 크기 물리 치수(핵심 5mm 이상) 측정
6. 서버 API 확정 후 `CarpoolRepository` REST 구현 교체
7. 제외 기능(음성 명령, TTS, 정산, 결제, iOS)은 이번 MVP 범위 밖. README에 정리
